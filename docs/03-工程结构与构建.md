## 2. 构建说明（Windows + MSVC + Qt6；M9 起实际验证，M13 起全部走 PowerShell）

前置：Qt 6.5+（含 Widgets/Multimedia/Network/Concurrent）、CMake 3.21+、
Visual Studio 2022（「使用 C++ 的桌面开发」工作负载，自带 MSVC 与 ninja）。

```powershell
.\scripts\build.ps1                     # Release，默认 build\ 目录
.\scripts\build.ps1 -Clean              # 清理后全量构建
.\scripts\build.ps1 -Config Debug -Jobs 4
.\scripts\build.ps1 -QtDir 'D:\Qt\6.8.3\msvc2022_64'
# 产物：build\src\AdoLoop.exe（结束时打印路径、字节数与 sha256）
```

`scripts\build.ps1` 实际做的事（等价于「先手工加载 MSVC 环境、再跑两条 cmake 命令」，
但全程纯 PowerShell，不经过任何批处理脚本；变迁过程见 `docs/11` M13 节）：

1. `vswhere` 枚举装了 VC++ x64 工具集的 VS 实例（完整 IDE 产品优先、版本降序），
   用 VS 自带的 `Common7\Tools\Launch-VsDevShell.ps1` 在**当前会话**加载 MSVC 环境
   （它内部加载 `Microsoft.VisualStudio.DevShell.dll` 并调用 `Enter-VsDevShell`）；
2. 从 PATH 剔除所有含 `mingw|msys|cygwin|strawberry` 的目录 → CMake 不会再误选 `gcc`；
3. 自动探测 Qt：`C:\Qt\<版本>\msvc2022_64`（取版本最高者），或 `-QtDir` / 环境变量
   `ADOLOOP_QT_ROOT`；并校验四个必需组件（Widgets/Multimedia/Network/Concurrent）都在；
4. ninja 优先用 VS 自带的 `Common7\IDE\CommonExtensions\Microsoft\CMake\Ninja\ninja.exe`；
5. `cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=<Qt>
   -DCMAKE_MAKE_PROGRAM=<VS ninja>` → `cmake --build build -j <CPU 核数>`；
6. 读 `CMakeCache.txt` 校验 `CMAKE_CXX_COMPILER` 确实是 `cl.exe`，否则以非零退出码报错。

> M9（2026-09-21）首次用 MSVC 19.44 + Qt 6.8.3 实机构建：configure / build 退出码均 0，
> clean build 44/44、零 warning，产物 `build/src/AdoLoop.exe`（564 KB）。
> 后续里程碑持续保持零 error / 零 warning：M10 47/47（644,608 字节）、M11 52/52（771,584 字节）、
> M12 55/55（904,192 字节）、**M13 55/55（904,192 字节，全量 clean build 35 秒）**。
> 构建过程中修复的问题清单见 `docs/11-进度日志.md`（M13 的两条与脚本自身有关，引擎未改一行）。

## 3. 外部工具与降级矩阵

| 组件 | 用途 | 缺失时行为 |
| --- | --- | --- |
| mpv.exe | 首选播放后端（JSON IPC，变速不变调） | 自动切 Qt Multimedia 后端（变速可能变调） |
| ffmpeg.exe | 波形解码、音频提取 | 波形区显示提示，不崩溃 |
| whisper-cli(.exe) | ASR 引擎 A（whisper.cpp） | 引擎 A 不可用，提示改用 faster-whisper |
| python3 + faster-whisper | ASR 引擎 B | 引擎 B 不可用，提示安装 |
| yt-dlp | 在线播放解析/字幕下载 | 打开 URL 时提示 |
| MeCab（M11，可选） | 日语分词增强（词/读音/原形） | 不触发该档，改用 python 桥或内置启发式 |
| python3 + janome/fugashi（M11，可选） | 日语分词增强（同上，经桥脚本） | 自动降级到内置启发式（默认档） |

所有外部工具路径可在「设置 → 通用/引擎」中显式配置，默认在 PATH 中探测
（`Subprocess::findExecutable`）。
**分词器两档外部引擎只在用户填了路径时才尝试**，因此默认情况下不会启动任何子进程。

构建/打包期依赖（M13，非运行期）：

| 工具 | 用途 | 缺失时行为 |
| --- | --- | --- |
| vswhere.exe | 定位 Visual Studio 实例 | build.ps1 报错并提示安装 VS 2022 / 生成工具 |
| `Launch-VsDevShell.ps1`（VS 自带） | 在 PowerShell 会话内加载 MSVC 环境 | build.ps1 报错（提示该实例缺少 VC++ 工具集） |
| VS 自带 ninja | Ninja 生成器 | 回退到 PATH 中的 `ninja.exe`，都没有则报错 |
| windeployqt.exe（Qt 自带） | 部署 Qt DLL 与插件 | package.ps1 报错 |
| `VC\Redist\MSVC\<版本>\x64\Microsoft.VC143.CRT` | 随包提供 MSVC 运行库 | 警告并跳过（目标机器需自装 VC++ 可再发行组件） |

## 5. 关键编译注意点（自检记录）

- `Sentence::chunks()` 使用 `QRandomGenerator`（弃用 `qsrand/qrand` 已规避）。
- `Settings.h` 对 `QSettings` 采用前置声明。
- CMake 开启 `AUTOMOC`，所有 QObject 子类信号/槽按惯例放头文件。
- 编译单元账目（M13 复核）：`src/CMakeLists.txt` 的 `ADOLOOP_SOURCES` 共 53 条
  （52 个 `.cpp` + 1 个仅供 AUTOMOC 处理的纯接口头 `asr/AsrEngine.h`）；
  ninja 报告的 **55/55** = 52 个工程 `.cpp` + 1 个 AUTOMOC 生成的 `mocs_compilation.cpp`
  + 1 个 AUTOMOC/AUTOUIC 生成步骤 + 1 个链接步骤。
- 本目录文档为过程记录，随里程碑推进更新。

## 6. 运行与便携发行包（M13）

### 6.1 scripts 一览

| 脚本 | 作用 | 关键参数 |
| --- | --- | --- |
| `scripts/build.ps1` | configure + build，输出产物路径/字节数/sha256 | `-Config` `-BuildDir` `-Jobs` `-QtDir` `-QtRoot` `-Generator` `-Clean` `-Target` `-VsInstallPath` `-NinjaExe` `-CMakeExe` |
| `scripts/package.ps1` | 产便携发行包 `dist\AdoLoop\` | 上面全部 + `-DistDir` `-SkipBuild` `-Zip` `-ZipPath` `-SkipTranslations` `-SkipOpenGlSw` `-SkipD3DCompiler` `-SkipCompilerRuntime` |
| `scripts/run.ps1` | 构建（可选）后启动，摆好运行期 PATH | `-SkipBuild` `-Exe` `-NoQtPath` `-NoWait` `-Offscreen` `-TimeoutSec` `-ExeArgs` + 构建参数 |
| `scripts/clean.ps1` | 清理生成目录（带安全校验） | `-Paths` `-KeepDist` `-ListOnly` `-WhatIf` |
| `scripts/common.ps1` | 上述四个脚本共用的函数库 | 点源加载，不直接运行 |

所有脚本幂等（可反复执行）、`$ErrorActionPreference='Stop'` + 显式检查 `$LASTEXITCODE`、
失败必以非零退出码结束、支持 `-Verbose`；不依赖任何第三方模块。
脚本文件以 **UTF-8 BOM** 保存（Windows PowerShell 5.1 需要 BOM 才能正确解析中文注释）。

**写入范围受限**：`-BuildDir` / `-DistDir` / `-ZipPath` 的顶层目录必须是
`build` / `build-*` / `dist` / `dist\*`（与 `.gitignore` 一致）且位于仓库内，
否则脚本直接拒绝执行（`Assert-AdoLoopWritableOutputPath`）。

> 注意：用 `powershell -File scripts\xxx.ps1` 调用时，PS 5.1 会把参数按字面字符串传递，
> **数组参数（`-Paths` / `-Target` / `-ExeArgs`）只能给一个值**。要传多个值请在 PowerShell
> 会话里直接运行脚本（`.\scripts\clean.ps1 -Paths 'a','b'`）。
