## M11 日语化（分词地基）+ 字幕悬停词级取词 + 词典发音朗读 + 听音查字（✅ 本次）

**前提修正**：用户实际学习语言是**日语**，而 M2～M10 整套代码按英语假设编写。最典型的坑是
`util/StringUtil::tokenizeWords()` 按「字母数字连续」切词，而 `QChar::isLetterOrNumber()`
对汉字/假名同样为真 —— 「私は学生です」会被整句当成**一个词**，所有「词级」功能（抠词听写、
取词查词、闪卡挖空、造句切词）实际全部落空。本次把分词改成语言感知，日语为默认。

### 第 1 块：日语分词地基

新增 `core/Tokenizer.{h,cpp}`（纯逻辑，**不依赖 app/Settings**，语言与外部引擎路径经参数注入）：

| 档位 | 触发条件 | 能力 | 本机状态 |
| --- | --- | --- | --- |
| ① MeCab | 设置里填了 MeCab 路径/命令名且可执行 | 词 + 读音 + 原形 | 未安装 → 不触发 |
| ② Python 桥 | 设置里填了 python 路径且 `scripts/japanese_tokenizer_bridge.py` 存在 | 词 + 读音 + 原形（janome / fugashi） | 未安装 janome/fugashi → 自动降级 |
| ③ **内置启发式** | 默认 | 词（无读音/原形） | **实际使用档** |

内置启发式（`Tokenizer::heuristicJapaneseTokens`，纯函数可单测）：

1. 按 Unicode 类别切 run：汉字（含 `々〆〇ヵヶ`、CJK 扩展 B 代理对）/ 平假名（含浊点）/
   片假名（含 `ー`、半角片假名）/ 拉丁（含全角）/ 数字 / 其他；
2. 片假名 / 拉丁 / 数字 run 各自整体成词（`コンピュータ`、`ABC`、`123`）；
3. 汉字 run + 后邻平假名 run：
   - 平假名 run **以助词/助动词白名单开头**（`は,が,を,に,で,と,も,へ,や,の,か,ね,よ,な,です,ます,…`）
     → 汉字不合并；白名单前缀切成独立词，其余部分另作一词
     （`私は学生です`→`私/は/学生/です`；`今日はいい…`→`今日/は/いい/…`）；
   - 否则该平假名 run ≤3 字 → 整体并入（`食べる`、`大きい`、`行きます`）；
   - >3 字 → 只并入 1 个送假名，其余独立（`食べなかった`→`食べ/なかった`；
     `学生ではありません`→`学生/で/はありません`）；
4. 独立平假名 run 整体成词、不强切（`おいしい`、`すしをたべる`）；
5. 标点/空白/记号丢弃（`strutil::isPunct` 补全角与日文约物 `、。！？「」『』・〜～` 等）；
6. 保序，并输出 `begin/length` 供字幕像素级命中。
7. `ー` 紧跟前一**平假名** run 时并入该 run（`らーめん`）；否则属片假名。

- 语言注入链路（core 不反向依赖 app）：`Settings::studyLanguage()`（默认 `"ja"`）→
  `AppController::studyLang()` → `SubtitleModel::setStudyLang()` → 每个 `Sentence.lang`；
  `Sentence::wordList()/estimatedWords()/clozeText()`、`DictationSession`、`SentenceBuilder`、
  `FlashcardModel` 全部走语言感知分词；英语行为与 M10 完全一致（有等价断言校验）。
- `SubtitleModel::setStudyLang()` 会清空旧的 `Sentence.tokens` 缓存（语言变了分词作废）。
- 设置界面：`源语言 (如 en)` 输入框 → **学习语言**下拉（日本語 / English）+ 源语言下拉；
  ASR 语言改为「跟随学习语言（默认）/ 手动指定」二选一；新增 MeCab 路径行（可选）。
- 配了 MeCab/python 时，字幕加载后走 `AppController::upgradeSentenceTokens()` 一次性批量升级
  （单次子进程、`maxBatchLines` 上限）；未配置则完全不启动子进程。
- `Sentence::estimatedWords()` 末词吸收整数取整余量，估计区间铺满整句（M11 小改进）。

**过程中被自检抓出的两个真 bug**（都是内置分词的实现问题，不是期望值问题）：
① 白名单前缀分支里 `++i` 把整段平假名 run 消费掉却没输出 → `は/です` 等助词全部丢失
（`私は学生です` 变成 `私/学生`）；② 原「长平假名串取最长前缀」规则会把 `食べなかった`
切成 `食べなか/った`，改为只并入 1 个送假名。

关键两行原文（其余同构）：

```just
set windows-shell := ["powershell.exe", "-NoProfile", "-ExecutionPolicy", "Bypass", "-Command"]

run *args:
	& '{{justfile_directory()}}/scripts/run.ps1' -SkipBuild {{trim_start_matches(args, "--")}}; exit $LASTEXITCODE
```

### 第 2 块：`just run` 不构建，在实现上是怎么保证的

1. **只传 `-SkipBuild`**：`run.ps1` 中 `Invoke-AdoLoopBuild` 只出现在 `else`（构建）分支，
   `-SkipBuild` 分支只做「找产物 → 找不到就 `throw`」；justfile 也不给它任何构建参数
   （`-Config` / `-Clean` / `-Target` 都不传）。`run-dist` 走的是 `-Exe` 分支
   （`-Exe` 在 `run.ps1` 里本身即隐含跳构建）。
2. **没有回落路径**：产物缺失 → `throw` → `catch` → `exit 1` → `just` 以 1 结束；
   脚本里不存在「找不到就顺手构建」的分支。
3. **可验证证据**（第 4 块验收 3）：把产物改名后 `just run` 以退出码 1 结束（同类的 `-Exe` 变体
   实测 `real 0m0.763s` 返回），且 `build\` 树 167 个文件的「mtime+size+路径」集合 sha1
   前后**完全一致**（无一次编译/链接）。

顺带改了两条「产物不存在」的报错文案（`scripts/run.ps1` 各一行，**不改语义**），让 just 用户一眼看到下一步：

```powershell
throw "-Exe 指定的文件不存在：$exePath（若这是构建产物，请先执行 .\scripts\build.ps1 或 just build）"
'        请先执行 .\scripts\build.ps1（或 just build），或去掉 -SkipBuild。'
```

### 第 3 块：Windows 下的三个坑（均实测）

1. **`--` 不会被自动吃掉**：`just run -- -Offscreen` 里 `{{args}}` 展开为 `-- -Offscreen`
   （`--` 只有写在 recipe 名**之前**才被 just 剥掉；`just -- run -Offscreen` 才是剥掉的那种），
   直接拼进命令行会被 PowerShell 当成 `--` 实参而报错。justfile 用
   `{{trim_start_matches(args, "--")}}` 剥掉开头多余的 `--`，于是
   `just run -- -Offscreen -TimeoutSec 5` 与 `just run -Offscreen -TimeoutSec 5` **两种写法都可用**。
2. **缩进 Tab / 行尾 LF**：第一版落盘时被写入工具转成了 4 空格（just 能容忍「全文一致的空格缩进」，
   但不符合要求），已改回 Tab，并用 `od -c` 逐字节确认：行首 `\t`、行尾 `\n`、无 BOM、无 CR。
3. **参数值不能带空格**：just 的变长参数按空格拼接（实测 `just probe -- "a b" c` → `a b c`），
   引号无法保留；已在 README 写明（需要带空格的参数时直接调用 `scripts\*.ps1`）。

### 第 6 块：过程中观察到的两件事（均不影响 justfile 正确性，如实记录）

1. **`just clean` 第 1 次以退出码 1 失败**：`[失败] 对路径"AdoLoop.exe"的访问被拒绝。`
   （卡在 `dist\AdoLoop\AdoLoop.exe`；`build\` 已删干净），紧接着重试即成功（退出码 0）。
   当时进程表里有一个**先于本轮工作存在**的残留 `AdoLoop.exe`（PID 20020，启动时间 22:16:57 ——
   即 M13 批量启动实验的遗留；`Path` 为空、工作集 32 KB，属于「已终止但句柄未释放」的条目）。
   事后专门做了复现测试（启动 dist exe → 3 秒后 Kill → **立刻**删除该 exe）→ **删除成功**，
   说明这不是 justfile / `clean.ps1` 的必然行为，而是 Windows 文件占用的一次性干扰。
   副产品：这次失败正好验证了「脚本非零退出 → `just` 非零退出」的传播是对的。
2. **`just package` 与 `just package -- -SkipBuild` 的发行包内容不同**（两种写法各复现 2 次）：
   - `just package`（默认，先构建）→ **69 文件 / 115.62 MB / 33 顶层条目**；
   - `just package -- -SkipBuild` → **67 文件 / 96.26 MB / 31 顶层条目**（与 M13 记录一致）。
   差异恰为两个文件：`dxil.dll`（1,509,744 字节）与 `vc_redist.x64.exe`（25,635,768 字节）。
   来源已核对：`vc_redist.x64.exe` 与 VS 的 `VC\Redist\MSVC\v143\vc_redist.x64.exe`
   **字节数与 mtime 完全一致**；`dxil.dll` 与 Windows SDK
   `bin\10.0.26100.0\x64\dxil.dll` 的 **mtime 一致**（大小差 16 字节，疑似 SDK 内另有同名文件）。
   `package.ps1` 自身并不复制这两个文件（它只复制 6 个 MSVC 运行库 DLL），
   是 `windeployqt` 在**「VS 开发环境已加载进 PATH」**时（`just package` 先跑构建 →
   同进程内 `Launch-VsDevShell.ps1` 生效）额外部署的。**属 M13 既有行为，本轮未改脚本、未改语义**，
   也不影响 `just run-dist` 的自检结论。
